# Cutter3000 1.2.0.00

Общая очередь удаления для двух существующих работников и ускоренный выбор порядка удаления объектов. [Сборка CFE](https://github.com/SmaginAV/Cutter3000/releases/download/v1.2.0.00/Cutter3000.cfe).

Работы по версии завершены, эксплуатационная приёмка пройдена. В рабочем прогоне на серверной базе ТОиР автотранспорта от Деснол скорость обрезки выросла примерно на **30–50%**. Это оценка общего ускорения, без инструментального распределения серверного времени по этапам.

## Изменения

- Целые независимые компоненты заранее упаковываются в задания примерно по 2000 узлов. Свободный работник получает следующий пакет без ожидания занятого соседа. Компонента крупнее этого размера остаётся целой.
- Оба работника используют один неизменяемый индекс опубликованного графа. Индекс освобождается после завершения всех его потребителей.
- Фиксация независимого пакета больше не вызывает полную повторную актуализацию общего графа. Свежие проверки ссылок, границ, прав и сохранности остаются в транзакции удаления. Изменившаяся компонента откатывается и возвращается на адресное перестроение.
- Для порций больше 64 объектов порядок удаления рассчитывается очередью зависимостей. Сохранены прежний приоритет доступных объектов и поведение при циклах. Прикладные обработчики выполняются обычными методами платформы.
- Технические пакеты не добавляют строки в пользовательскую таблицу. Их прогресс и ошибки учитываются в логических работах.

## Результаты проверки

Локальная файловая база, платформа 8.3.27.2074, 4560 документов в 120 компонентах. По три прогона каждого варианта; сравнение с 1.1.0.40, медианы:

| Сценарий | 1.1.0.40 | 1.2.0.00 | Изменение |
|---|---:|---:|---|
| Между подготовкой и выдачей зафиксирована независимая работа | 21,192 с | 13,449 с | Время −36,5%; скорость ×1,576 |
| Независимой фиксации не было | 16,624 с | 13,203 с | Время −20,6%; скорость ×1,259 |

Это измерения локального последовательного контура, а не коэффициент ускорения серверной обрезки ТОиР. Условие отсутствия замедления абсолютно каждого этапа не подтверждено: публикация с записью заголовков очереди выросла на 8–9 мс, в первом сценарии построение графа — на 46 мс. Удаление с очисткой ускорилось примерно на 30%. [Все этапы и границы проверки](../performance-v1.2.0.00.md).

Пройдены проверки остановки во время обработчика записи, сохранности данных при изменении каскада, изоляции ошибки одной компоненты, независимой выдачи и отображения прогресса. Порядок удаления совпал с прежним алгоритмом на 400 детерминированных графах с циклами, повторяющимися связями и внешними владельцами. Повторена 31 прежняя регрессия. Общая очередь проверена при управляемых и автоматических блокировках.

Проверены применимость и компиляция в четырёх контекстах на универсальной конфигурации и предоставленном CF ТОиР. Обратная выгрузка всех 20 BSL-модулей совпала с исходниками. Инструментальные серверные замеры по этапам, отдельные испытания конкурирующих транзакций PostgreSQL и выполнение на WMS в этом контуре не проводились. Изменения обфускации в версию не включались.

## Обновление

Завершить текущий запуск и дождаться выхода его фоновых заданий. Установить версионный CFE 1.2.0.00, применить изменение структуры служебных регистров и перезапустить сеансы. Начать новый запуск: перенос работающей очереди между версиями не предусмотрен.
